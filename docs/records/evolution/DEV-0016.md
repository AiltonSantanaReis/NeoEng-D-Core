# DEV-0016 — Reconcile EV-05 stage-scope maximum before CS022

Status: **PROSPECTIVE CS000P DECISION / NOT YET ACCEPTED**

## Context

After protected integration of CS000O, EV-04 is accepted and the evolution
roadmap identifies EV-05 as the next stage with planned ChangeSet CS022.

The active higher-precedence machine ledger
`audit/STAGE_SCOPE_MAXIMA.json` still lists EV-05 under
`undefined_stages` and states that an undefined stage cannot be prepared,
started or operated until an accepted prior governance amendment defines its
maximum scope.

Accordingly, no CS022 implementation may begin yet.

## Decision

Define a narrow maximum for EV-05 before CS022 starts.

The maximum permits only the files needed to:

- advance EV-05 / EVREQ-019..021 lifecycle ledgers prospectively in CS022;
- define and bind CS022 validation;
- add one dedicated semantic fuzz/corruption test executable;
- wire that executable into CMake;
- compare deterministic rejection classifications across declared compiler
  environments in the dedicated workflow;
- preserve the repository manifest and ChangeSet descriptor.

The maximum does not authorize runtime, public-header, app, historical fuzz
target/corpus, contract-document or golden-corpus changes.

## Protected boundaries

CS022 remains forbidden from changing:

- `src/**`;
- `include/**`;
- `modules/**`;
- `apps/**`;
- `fuzz/**`;
- `cmake/**`;
- `docs/governance/**`;
- `docs/contracts/**`;
- EV-03 golden corpus bytes;
- EV-04 property/model implementation;
- CS021 and CS000O accepted evidence;
- permanent trusted ChangeSet validation;
- permanent current-product regression;
- the stage-scope maximum itself.

Any real need to cross one of those boundaries requires a new prospective
governance decision before implementation.

## Lifecycle boundary

CS000P does not start EV-05.

Until CS000P is VALIDATED, ACCEPTED and protected-integrated:

- `current_stage` remains `EV-04`;
- EV-04 remains `accepted`;
- EV-05 remains `not_started`;
- CS022 remains dormant;
- EVREQ-019..021 remain `planned`;
- release remains unauthorized.

After accepted protected integration, CS022 may be prepared only within the
newly defined EV-05 maximum.
