# DEV-0013 — Reconcile EV-04 stage-scope maximum before CS021

Status: **PROSPECTIVE CS000M DECISION / NOT YET ACCEPTED**

## Context

After protected integration of CS000L, EV-03 is accepted and the evolution
roadmap identifies EV-04 as the next stage with planned ChangeSet CS021.

Before CS021 implementation, review of the active source-of-truth precedence
identified a higher-precedence machine ledger conflict:

`audit/STAGE_SCOPE_MAXIMA.json`

still listed EV-04 under `undefined_stages` and contained the rule that an
undefined stage cannot be prepared, started or operated until an accepted
prior governance amendment defines its maximum scope.

The prospective ChangeSet-validation regime simplified ChangeSet execution,
but did not remove `STAGE_SCOPE_MAXIMA.json` from the active source-of-truth
index.

Accordingly, implementation stopped before any CS021 file was modified.

## Decision

Define a narrow maximum for EV-04 before CS021 starts.

The maximum permits only the files needed to:

- advance EV-04/EVREQ-016..018 lifecycle ledgers prospectively;
- define and bind CS021 validation;
- add one dedicated property/model test executable;
- wire that test into CMake;
- preserve the repository manifest and ChangeSet descriptor.

The maximum does not authorize runtime or public-contract implementation
changes.

## Protected boundaries

CS021 remains forbidden from changing core runtime/source/header surfaces and
from changing the EV-03 golden corpus.

In particular, CS021 must not modify:

- `src/**`;
- `include/**`;
- `tests/golden/ev03/v1/**`;
- `docs/contracts/GOLDEN_CORPUS_V1.md`;
- CS000L accepted evidence;
- trusted permanent ChangeSet validation;
- permanent current-product regression;
- the stage-scope maximum itself.

## Historical interpretation

This decision is prospective.

It does not rewrite, invalidate, reclassify or reinterpret the already accepted
EV-00 through EV-03 history.

The inconsistency discovered in the historical stage-scope ledger is preserved
as historical state; CS000M resolves only the currently affected future stage,
EV-04.

## Lifecycle boundary

CS000M does not start EV-04.

Until CS000M is VALIDATED, ACCEPTED and protected-integrated:

- EV-04 remains `not_started`;
- CS021 remains dormant;
- EVREQ-016..018 remain `planned`;
- release remains unauthorized.

After accepted protected integration, CS021 may be resumed only within the
newly defined EV-04 maximum.
