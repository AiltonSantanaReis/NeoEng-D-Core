## Root cause

The CS016C verifier permanently applied an exact historical byte comparison to
lifecycle-mutable operational ledgers, especially `audit/EVOLUTION_ROADMAP.json`.
That check was valid while proving CS016C did not rewrite prior state, but was
not a valid timeless invariant: an authorized stage lifecycle must change the
roadmap.

The defect therefore confused historical/normative immutability with operational
ledger immutability.

## Corrective action

CS016D / Amendment 1.4:

1. distinguishes immutable accepted normative/evidence artifacts from
   lifecycle-mutable operational ledgers;
2. reexecutes the full accepted v1.3 verifier and self-test at exact snapshot
   `7393b32d2be3fd2e65eab6a738a0066c13848f6c`;
3. preserves accepted normative/evidence artifacts byte-for-byte;
4. validates current operational ledgers semantically for the current lifecycle;
5. added permanent `SCN-REGRESSION-004`;
6. added `EVREQ-074` and `INV-EV-030`;
7. preserves Action Authorization regressions 001/002/003;
8. qualified source `3831d1080059811fe3f7e906607ef8c60917dae0` in
   workflow run `31615538151`, job `94177285913`.

The qualifying run passed Action Authorization self-test, D-Lab self-test and
verifier, required-amendments gate, evolution self-test/verifier, product
contract, product assurance and tracked-file manifest.
