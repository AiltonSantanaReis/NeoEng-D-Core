# DEV-0004 — D-Lab verifier lifecycle-scope defect

Status: `OPEN_UNTIL_CS016D_ACCEPTED`  
Program: `POST_1_14_1`  
Affected stage: `EV-00 / CS017`  
Classification: `governance / verifier / lifecycle-scope`

## Detection

After CS016C was accepted, merged and post-merge validated at
`7393b32d2be3fd2e65eab6a738a0066c13848f6c`, the official governance run
reported EV-00 `not_started`, CS016A/B/C accepted and
`prepare_stage_changeset(CS017) => AUTHORIZED`.

CS017 R3 was rebuilt from that exact `main` and produced control commit:

`5c5f328afc919527775742c702e3d1a47c1490c9`

The branch changed EV-00 only from `not_started` to `in_progress` and added
CS017 preparation records. No D-Lab harness or qualifying product command had
been created or executed.

Workflow run `31613924661`, job `94171862183`, then failed at:

`D-LAB GOVERNANCE SELF-TEST: REJECT`

with exact reason:

`protected v1.2 file changed during CS016C: audit/EVOLUTION_ROADMAP.json`

The Action Authorization self-test immediately preceding this failure passed.

## Immediate containment

- STOP CS017 R3 before `stage_operation`;
- no manifest reconciliation of the failed start state;
- no harness/workflow publication;
- no baseline build or qualifying product campaign;
- no edit to roadmap or tests to hide the failure;
- R3 branch/run preserved as blocker evidence;
- product/runtime unchanged;
- official `main` remains at post-CS016C state with EV-00 `not_started`.

## Root cause

The CS016C verifier implementation used a permanent `PROTECTED_EXACT` comparison
against the pre-CS016C snapshot and included operational ledgers such as
`audit/EVOLUTION_ROADMAP.json`.

That check was suitable for proving the CS016C correction did not rewrite prior
state while CS016C itself was being accepted, but it was incorrectly retained
as a timeless invariant. A later, explicitly authorized lifecycle transition of
EV-00 therefore became indistinguishable from a retroactive rewrite of CS016C.

The normative roadmap is expected to change lifecycle state. Freezing it forever
would make `start_stage`/`advance_stage` structurally impossible.

CS016A/B/C and reexecute the accepted v1.3 verifier on its exact accepted
snapshot rather than weaken that historical proof.
