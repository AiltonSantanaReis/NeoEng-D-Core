# DEV-0005 — Governance root-of-trust / anti-masking gap

Status: `in_progress`

## Descoberta

Identificado após a aceitação e merge de CS016D (`de55e0882c6400a0409b5cf881c6ee796a975cdf`) e durante auditoria do start-state de CS017 R4.

CS017 R4:

- branch: `agent/cs017-ev00-baseline-certification-r4`;
- source auditado: `253859d285963a2519af78cd7a30ba2d69fad9a1`;
- governance run: `31618330920`;
- conclusão desse run: `success` para os gates então existentes;
- qualifying EV-00 campaign executada antes do STOP: **não**;
- reutilizável como qualifying evidence: **não**.

## Classe de desvio

Governança / root of trust / authorization scope / evidence provenance / repository protection.

## Falhas de desenho encontradas

1. ações de escrita podiam omitir paths em trajetórias existentes;
2. o verificador de diff confiava no `control_base_commit` e allowlist do próprio scope candidato;
3. o próprio scope podia estar dentro de seu allowlist;
4. evidência local íntegra não provava, sozinha, proveniência oficial do GitHub Actions;
5. aceitação candidato/accepted/merge/post-merge não formava uma cadeia criptográfica append-only única;
6. autorização de advance/release não era autocontida no mesmo nível do contrato normativo;
7. `main` estava sem branch protection/ruleset no momento da auditoria;
8. faltava um máximo independente para escopos futuros;
9. faltava um verifier executado a partir da base confiável, independente do código candidato.

## Impact analysis

Não foi identificada evidência de que CS016A/B/C/D tenham usado essas brechas para aprovar resultado falso. Runs e SHAs históricos foram conferidos contra o GitHub durante a auditoria.

O risco é prospectivo: uma alteração futura poderia tentar modificar simultaneamente regra, scope, verifier e evidência de modo autoconsistente.

## Decisão

`STOP` antes de `stage_operation` de CS017 R4.

Criar CS016E como correção exclusiva de governança. R4 não será retomado depois da correção. EV-00 só poderá continuar em nova tentativa criada a partir da `main` pós-CS016E.

## Critério de fechamento

DEV-0005 só pode ser fechado quando:

- root-of-trust e stage maxima estiverem integrados;
- SCN-REGRESSION-005 estiver `passed` com evidência real;
- cadeia A/B/C/D estiver validada contra a API oficial;
- `main` estiver protegida conforme política;
- PR de CS016E tiver checks exigidos e aprovação independente;
- merge real e post-merge run real estiverem registrados;
- entrada CS016E for anexada à acceptance chain sem reescrever A/B/C/D.
