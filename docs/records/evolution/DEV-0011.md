# DEV-0011 — CS020 cross-platform frozen-reference binding amendment

Decision: **AUTHORIZED PRE-EXECUTION CS020 FREEZE AMENDMENT / NOT YET QUALIFIED / NOT ACCEPTED**

Stage: `EV-03`

ChangeSet: `CS020`

Integrated base:

`98c1042249ced4c1775dddf9a871e29dc6070828`

## Context

CS020 had materialized its deterministic golden corpus locally and staged the
initial 18-path source candidate. No source commit, remote branch, qualifying
workflow execution, validation result, acceptance decision or release
authorization existed.

During the precommit proof of the 53-file frozen inventory, eleven historical
product/reference paths showed a difference between the current index Git blob
and `git hash-object --path`.

A dedicated read-only diagnostic established that this was not a local content
modification:

- the raw worktree blob equals the index blob;
- the index blob equals the exact integrated-base blob;
- `assume-unchanged` is false;
- `skip-worktree` is false;
- byte-for-byte comparison of the historical Git blob and local worktree is
  equal;
- each affected historical blob contains CRLF;
- the current repository checkout policy is `text=auto eol=lf`;
- applying the current clean normalization produces a different prospective
  blob.

The affected paths are:

- `include/neoeng/core/fixed.hpp`;
- `include/neoeng/core/hash.hpp`;
- `include/neoeng/core/rollback.hpp`;
- `include/neoeng/core/simulation.hpp`;
- `include/neoeng/core/snapshot_store.hpp`;
- `include/neoeng/core/types.hpp`;
- `src/hash.cpp`;
- `src/rollback.cpp`;
- `src/simulation.cpp`;
- `src/snapshot_store.cpp`;
- `tests/test_main.cpp`.

## Governance impact

The prospective ChangeSet verifier freezes `frozen_files` by comparing raw
bytes from `git show(plan_commit:path)` with bytes materialized in the current
checkout.

The trusted acceptance gate checks the candidate in Ubuntu. Under the current
`eol=lf` policy, the eleven historical CRLF blobs are checkout-sensitive even
though their Git object identities are unchanged.

Leaving those paths in the generic worktree-byte freeze would therefore create
a platform-induced false rejection during future binding.

Normalizing the eleven historical product/reference files merely to satisfy
the verifier would create an unrelated product-source diff.

Weakening or removing the repository `eol=lf` policy would alter a repository
control outside the technical objective.

Both alternatives are rejected.

## Authorized amendment

Before any qualifying execution:

1. preserve the eleven historical files byte-for-byte and Git-object-for-Git-
   object;
2. remove only those eleven checkout-sensitive paths from the generic
   worktree-byte `frozen_files` mechanism;
3. bind all eleven paths by exact Git blob identity in the CS020 golden
   manifest;
4. require the CS020 verifier to prove candidate Git blob identity against the
   exact integrated base;
5. add `.gitattributes` to the generic frozen inventory so the checkout policy
   itself is protected;
6. add this `DEV-0011` record to source scope and generic frozen inventory;
7. keep all 28 required tests unchanged;
8. keep the deterministic corpus coverage unchanged;
9. do not invoke the golden emitter again;
10. regenerate only metadata affected by this amendment.

- alter `.gitattributes`;
- alter runtime semantics;
- alter public API or Host SDK ABI;
- alter canonical serialization;
- alter stable hash, SHA-256 or Merkle semantics;
- alter snapshot, rollback or replay behavior;
- alter deterministic diagnostics;
- alter any already emitted `.bin` golden artifact;
- alter `corpus.json`;
- reduce or remove any required test;
- start EV-04 or EV-05;
- authorize release.

`manifest.json`, the CS020 plan, ChangeSet record, contract, verifier, workflow
and repository manifest may change only as necessary to encode and verify this
pre-execution amendment.

removed or weakened.

`INV-EV-020` is satisfied by STOP, this explicit deviation record, prospective

The amendment itself is not acceptance. Qualification and exact run binding
remain future gates.
