`Verify bootstrap repository protection` falhou com:

`cannot read branch metadata: HTTP 403`

O secret `GOVERNANCE_ADMIN_TOKEN` estava presente no ambiente do job (valor redigido pelo GitHub Actions), portanto esta falha não foi causada por secret ausente.

## Causa raiz

`scripts/verify_repository_protection.py` consultava primeiro `GET /repos/{owner}/{repo}/branches/{branch}` usando o fine-grained PAT administrativo. Para repositório privado, esse endpoint exige `Contents: read`. A política de CS016E, porém, deliberadamente especifica um token de menor privilégio com `Administration: read`, que é suficiente para `GET /repos/{owner}/{repo}/branches/{branch}/protection` — o endpoint efetivamente necessário para verificar approvals, stale reviews, status checks, admin enforcement, force-push e deletion.

## Correção

A chamada redundante ao endpoint de metadata da branch foi removida. O verificador passa a consultar diretamente o endpoint de branch protection e continua fail-closed para qualquer HTTP diferente de 200 ou resposta inválida.

O token **não** foi ampliado com `Contents: read`. A correção preserva o princípio de menor privilégio e não relaxa nenhum requisito de proteção.

Esta falha não é aprovação e permanece como evidência histórica do bootstrap CS016E.

Reconciliation trigger: solicitado após a correção de menor privilégio; o reconciliador permanece autorizado a alterar apenas `MANIFEST.sha256`.
